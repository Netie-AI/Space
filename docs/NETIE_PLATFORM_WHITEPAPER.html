The gate contract (real, in code)

cortex_client.gate_user_text() runs secure_message + classify. Business mode hard-blocks if the engine is offline ("Cortex engine required for Business safety but is offline"); personal chat soft-fails so a dead sidecar never breaks a demo. That asymmetry is the whole governance story in one function.

The token-map / unmask layer you asked about

It does not exist yet. Today's redaction is destructive — john@acme.com → [REDACTED:email] — so there is no way to restore the real value after the model answers. Your design ("token map with unmask layer, tokens stay inside, send masked data") needs a reversible vault: replace PII with format-preserving tokens (EMAIL_7f3a), keep the token→plaintext map local, encrypted, never egressed, and unmask on the response. That's §09.1 below and the highest-value security build.

05

Is the agent reproducible? Is the output trusted?

You asked directly: is it reproducible, is the output trusted, does it follow the pre-send pipeline. Straight answers.

Reproducibility

Deterministic stages: yes. The compliance engine, PII regex, injection guard, tier bounding, and cost ceiling are pure functions of their input — same input, same output, and every decision is auditable. Model stages: no, not by default — temperature, provider-side model updates, and non-pinned versions all introduce drift. To make an agent run reproducible you need four things, none fully wired yet:

  • Planned Pin {provider, model, version, temperature, seed} per node and record it in the run trace.
  • Planned Deterministic-first judgment: rules decide tier; the classifier only breaks ties (the router already prefers bounded rules).
  • Shipped A content-addressed store (CortexOS/cas/store.py) so identical inputs hit cache instead of re-inferring.
  • Partial A per-run decision trace (tier chosen, rules fired, cost) → today partly in the ledger, needs a first-class "run manifest."

Trusted output

Trust here means provenance + containment, not "the model is always right." What's genuinely true today: every governed message passes the injection/PII/scam gate before a prompt is built; the compliance verdict is deterministic and explainable; and the action is written to a tamper-evident hash chain you can verify(). What is not yet true, and must not be claimed to a customer:

ClaimRealityStatus
"PII never reaches a model"True for NRIC/email/card/phone patterns; misses names, addresses, account numbers, free-text identifiers (regex has no NER).Overclaim risk
"Data is masked and re-identified safely"Masking is one-way; there is no unmask. Re-identification isn't possible or verifiable yet.Gap
"Transport is TLS 1.3, MITM-safe"Only if Caddy terminates TLS at deploy. No cert pinning / mTLS in app; transport.py empty.Planned

07

OmniRoute: the free-tier fallback router (and the line we don't cross)

OmniRoute (cloned, v3.8.49) is "The Free AI Gateway" — a Node/TS monorepo that aggregates the documented free tiers of 268 providers behind one OpenAI-compatible endpoint, with auto-fallback, token compression, MCP/A2A, and a MITM proxy that reroutes Claude Code / Cursor / Cline. Critically, it relies on the user bringing their own keys and it itself ToS-flags 15 providers for you to decide on.

The legitimate integration

Fits Cortex cleanly as one more provider adapter under CortexOS/routing/adapters/. When a user's own paid quota/subscription ends, the router falls back to free-tier capacity the user or Netie legitimately holds, honoring each provider's terms:

flowchart LR
  req["Request needs a model"] --> q{"User quota / subscription active?"}
  q -- active --> paid["Route to user's paid tier"]
  q -- ended --> ff{"Free-tier fallback enabled & ToS-clean?"}
  ff -- yes --> omni["OmniRoute adapter → documented free tiers (BYO-key)"]
  ff -- no --> deny["Return 'quota ended' notice + upsell"]
  omni --> resp["OpenAI-compatible response → unmask → user"]
  paid --> resp
What I will not build — and why

The request as written — "login with our account, auto-create accounts at all these suppliers, route free APIs after subscriptions end" — has two parts I can't implement:

1. Automated account creation / bot sign-ups at third-party providers. This is prohibited regardless of authorization, and it breaks essentially every provider's ToS (and often triggers anti-abuse/CAPTCHA systems). Accounts must be created by a human.

2. Deliberately evading paid-subscription enforcement. Falling back to a provider's official free tier that you legitimately signed up for is fine. Farming disposable accounts to dodge a provider's paywall is not — it's the exact behavior OmniRoute itself flags and disclaims.

The buildable version: a BYO-key credential vault where you (or the end-user) paste keys you already own; Cortex routes/fallbacks across them within each provider's terms, meters usage, and shows the live free-tier budget — the honest version of "default they get free capacity."

08

Security deep-dive: the hard asks

PII v2 — layered detection

pii.py → +NER

Keep regex as the fast pre-filter; add a local NER (spaCy / Presidio analyzers) for names/addresses; fall back to MS Presidio or AWS Comprehend only when local confidence is low. All three feed one redact_for_prompt choke-point.

Reversible token vault

new: security/token_vault.py

Format-preserving tokens (EMAIL_7f3a) replace PII; the token→plaintext map is AES-256-GCM encrypted and never leaves the host. Unmask runs on the model's response inside the trust boundary.

RAM-safety

crypto/ephemeral_keys.py

Zeroize plaintext buffers after use; hold secrets in OS stores (Windows DPAPI / credential locker), not env vars; envelope-encrypt at rest; short-lived in-memory keys.

Transport hardening

crypto/transport.py (empty)

TLS 1.3 via Caddy plus app-level mTLS + cert pinning between AirGPT↔Cortex to defeat MITM, and token-bound sessions so a stolen bearer can't replay.

Sandbox tiers

wasm_isolate.py + Win Sandbox

Pyodide/WASM for light scripting (fuel + zero-imports, already real); Windows Sandbox / Firecracker / gVisor for compiled binaries & .exe. Enforce the memory cap that's currently declared-not-applied.

Magic-byte + egress

new: pre-parse + allowlist

Validate file signatures before any parser touches bytes (defeats polyglot/spoofed uploads). Outbound: destination allowlist + proxy + DLP so the engine can only talk to approved inference endpoints.

Cortex → Huawei: the integration fit (honest)

Cortex is a FastAPI service with local-model support, WASM isolation, deterministic compliance, and a tamper-evident ledger. That profile maps to Huawei's sovereign/enterprise story in three concrete ways — but note this is architecture-fit, not a signed path; any real motion needs BD and a partner agreement.

Ascend NPU backend

Add an adapters/ascend.py that targets CANN / MindSpore-served models for T1–T2 local inference, so the self-hosted tiers run on Huawei silicon.

Governance overlay

Sell Cortex as the audit + PII + compliance gateway in front of Huawei Cloud model APIs (incl. Pangu) — the "inference gateway with proof" layer regulated customers require.

Marketplace / on-prem

Package the Docker Compose + Caddy stack as a Huawei Cloud Marketplace ISV image, or an on-prem sovereign appliance where data never leaves the customer's boundary.

The selling point isn't the model — it's that every call is masked, routed, sandboxed, and provably logged, which is exactly what a carrier-grade / regulated buyer needs and what a bare model endpoint doesn't provide.
